## 1. Reinforcement Learning (RL)

### 1-Liner Definition

Reinforcement Learning is a type of machine learning in which an agent learns what to do by interacting with an environment and receiving rewards or penalties.

### Short Technical Explanation

Unlike supervised learning, where a model learns from labeled examples, reinforcement learning learns through **trial and error**.

Imagine teaching a dog a trick:

- The dog performs an action.
- You give it a treat when it does something correctly.
- It learns which actions lead to rewards.
- Over time, it improves its behavior.

An RL agent follows a similar process, trying to maximize its total reward over time.

### Real-World Scenarios

- **Gaming:** An AI learns to win chess or video games.
- **Robotics:** A robot learns to walk or grasp objects.
- **Autonomous driving research:** An agent learns driving decisions in a simulated environment.
- **LLMs:** Reinforcement learning can help optimize an AI assistant's responses according to human preferences.

### Code Snippet

This simple example illustrates the idea of an agent learning to choose an action that produces a reward.

```python
rewards = {
    "left": -1,
    "right": 10
}

action = "right"
reward = rewards[action]

print("Action:", action)
print("Reward:", reward)
```

Output:

```text
Action: right
Reward: 10
```

This is only a reward demonstration, not a learning algorithm. A real RL agent must learn which action is better from experience.

## 2. Agent, Environment, State, Action, Reward

These are the fundamental building blocks of reinforcement learning.

### 2.1 Agent

**1-Liner Definition:** The agent is the learner that makes decisions.

**Short Technical Explanation:** It observes the current situation, selects an action, and uses experience to improve its future decisions.

**Real-World Scenarios:**

- A robot deciding how to move.
- An AI playing chess.
- A simulated delivery robot choosing its route.

**Code Snippet:**

```python
class Agent:
    def choose_action(self, state):
        if state < 5:
            return "right"
        return "stop"

agent = Agent()
print(agent.choose_action(2))
```

### 2.2 Environment

**1-Liner Definition:** The environment is everything the agent interacts with.

**Short Technical Explanation:** It receives the agent's action, updates its situation, and provides the next state and reward.

**Real-World Scenarios:**

- A game board for a game-playing agent.
- A simulated road for a driving agent.
- A warehouse for a robot.

**Code Snippet:**

```python
class Environment:
    def step(self, action):
        if action == "right":
            return "Moved right"

env = Environment()
print(env.step("right"))
```

### 2.3 State

**1-Liner Definition:** A state describes the agent's current situation.

**Short Technical Explanation:** The state contains information the agent uses to choose its next action. In a grid game, it could be the agent's position; in a robot, it could include position, velocity, and sensor readings.

**Real-World Scenarios:**

- **Chess:** Positions of all pieces.
- **Robot:** Current location and joint positions.
- **Game:** Player health, score, and position.

**Code Snippet:**

```python
state = {
    "position": 3,
    "energy": 80
}

print(state["position"])
```

### 2.4 Action

**1-Liner Definition:** An action is a decision or move made by the agent.

**Short Technical Explanation:** Actions are selected based on the current state and the agent's policy. The environment responds to the chosen action.

**Real-World Scenarios:**

- A robot moves left or right.
- A game agent attacks or defends.
- A recommendation system selects an item to show, in an appropriate sequential decision-making setup.

**Code Snippet:**

```python
actions = ["left", "right", "stay"]

chosen_action = "right"
print(chosen_action)
```

### 2.5 Reward

**1-Liner Definition:** A reward is a numerical signal indicating how desirable an outcome is.

**Short Technical Explanation:** The environment gives a reward after an action. Positive rewards encourage desirable outcomes, while negative rewards discourage undesirable ones. The agent usually aims to maximize cumulative reward, not just the immediate reward.

**Real-World Scenarios:**

- A game agent earns points for winning.
- A robot receives a reward for reaching its destination.
- A simulated vehicle gets rewarded for safe progress and penalized for collisions.

**Code Snippet:**

```python
if reached_goal:
    reward = 10
else:
    reward = -1

print(reward)
```

Here, `reached_goal` would need to be defined by the environment.

### Remember the Difference

| Term | Simple Meaning | Example: Robot |
|---|---|---|
| Agent | Who decides? | Robot controller |
| Environment | Where does it act? | Room |
| State | What is happening now? | Robot's position |
| Action | What does it do? | Move forward |
| Reward | How good was the outcome? | +10 for reaching the goal |

## 3. Policy

### 1-Liner Definition

A **policy** is the strategy an agent uses to decide which action to take in a given state.

### Short Technical Explanation

A policy is commonly represented by `π(a | s)`, the probability of choosing action `a` when in state `s`.

There are two common types:

- **Deterministic policy:** Always chooses the same action for a given state.
- **Stochastic policy:** Assigns probabilities to different possible actions.

For example, a robot might choose to move right whenever the goal is to its right. A stochastic policy might choose right 80% of the time and left 20% of the time.

### Real-World Scenarios

- Game AI choosing whether to attack or defend.
- A robot choosing its next movement.
- An AI assistant learning how to respond to a prompt.

### Code Snippet

```python
def policy(state):
    if state < 5:
        return "right"
    return "left"

print(policy(2))  # right
print(policy(8))  # left
```

This is a simple, manually defined policy, not a learned one.

**Remember:** Policy = *What should I do?*

## 4. Value Function

### 1-Liner Definition

A **value function** estimates how much future reward an agent can expect from a state or action.

### Short Technical Explanation

An agent should not only consider the immediate reward. It should also consider the rewards it might receive later.

There are two important forms:

- **State-value function `V(s)`:** Expected future return starting from state `s` and following a policy.
- **Action-value function `Q(s, a)`:** Expected future return when taking action `a` in state `s`, then following a policy.

Future rewards are often discounted using `γ`, a number between 0 and 1.

```text
G_t = R_(t+1) + γR_(t+2) + γ²R_(t+3) + ...
```

Here, `G_t` is the cumulative discounted return.

### Real-World Scenarios

- A game-playing agent estimates which board positions are promising.
- A robot evaluates whether a position is likely to lead to its destination.
- A delivery agent evaluates which route may produce the best overall outcome.

### Code Snippet

```python
immediate_reward = 2
future_reward = 10
gamma = 0.9

value = immediate_reward + gamma * future_reward

print(value)  # 11.0
```

This is a one-step illustration of discounted return, not a trained value function.

**Remember:** Value function = *How good is this situation in the long run?*

## 5. Q-Learning

### 1-Liner Definition

**Q-Learning** is a model-free reinforcement learning algorithm that learns how valuable each action is in each state.

### Short Technical Explanation

Q-learning maintains a table of Q-values, where each entry represents the estimated long-term value of taking an action in a particular state.

It updates these estimates using experience:

```text
Q(s, a) ← Q(s, a) + α [r + γ max Q(s', a') - Q(s, a)]
```

Understand each symbol:

| Symbol | Meaning |
|---|---|
| `s` | Current state |
| `a` | Action taken |
| `r` | Reward received |
| `s'` | Next state |
| `α` | Learning rate |
| `γ` | Discount factor |
| `max Q(s', a')` | Best estimated next-state action value |

The agent repeatedly tries actions, receives rewards, and updates its Q-values. Over time, the estimates can guide it toward better decisions.

### Real-World Scenarios

- Learning to navigate a grid or maze.
- Training agents in simple simulated games.
- Teaching an agent to select actions in a small, discrete environment.

Q-learning is particularly useful for understanding RL before moving to deep reinforcement learning.

### Code Snippet: Q-Learning Update

```python
# Existing estimate
q_value = 2.0

# Experience from the environment
reward = 5
best_next_q = 4.0

learning_rate = 0.1
gamma = 0.9

new_q = q_value + learning_rate * (
    reward + gamma * best_next_q - q_value
)

print(round(new_q, 2))  # 2.66
```

The Q-value increases from `2.0` to `2.66` because the observed reward and estimated future reward suggest that the action is more valuable than previously estimated.

## 6. Exploration vs. Exploitation

### 1-Liner Definition

**Exploration vs. exploitation** is the trade-off between trying new actions to learn and using actions that already seem rewarding.

### Short Technical Explanation

An agent faces two choices:

- **Exploration:** Try an unfamiliar action to discover whether it is better.
- **Exploitation:** Choose the action currently believed to provide the highest reward.

A common method is **epsilon-greedy**:

- With probability `ε`, choose a random action.
- Otherwise, choose the action with the highest current Q-value.

For example, if `ε = 0.1`, the agent explores 10% of the time and exploits 90% of the time, subject to the random-selection rule.

### Real-World Scenarios

- **Games:** Trying a new strategy versus using a proven one.
- **Robotics:** Testing an unfamiliar movement versus repeating a successful movement.
- **Recommendations:** Exploring new items versus recommending items that have worked well before.

### Code Snippet

```python
import random

q_values = {
    "left": 2,
    "right": 8
}

epsilon = 0.1

if random.random() < epsilon:
    action = random.choice(list(q_values))
else:
    action = max(q_values, key=q_values.get)

print(action)
```

This code may print `right` most of the time, but sometimes chooses a random action.

### Reference Project

- [Gymnasium training tutorials](https://gymnasium.farama.org/tutorials/training_agents/) — study the exploration strategy in the Q-learning examples.

**Remember:** Exploration = *What else might work?* Exploitation = *What already works best?*

## 7. Reinforcement Learning from Human Feedback (RLHF)

### 1-Liner Definition

**RLHF** is a technique that uses human preferences to help train an AI model to produce responses people prefer.

### Short Technical Explanation

RLHF is widely associated with aligning large language models (LLMs) with human preferences.

A common traditional RLHF pipeline has three main stages:

### Step 1 — Supervised Fine-Tuning (SFT)

The model learns from example prompts and high-quality human-written responses.

### Step 2 — Human Preference Data and Reward Model

Humans compare alternative responses. A reward model learns to estimate which responses people prefer.

### Step 3 — Reinforcement Learning

The language model is optimized to obtain higher reward-model scores while controlling how far it moves from the original model.

A common RL algorithm in this traditional pipeline is PPO (Proximal Policy Optimization). Other preference-optimization methods also exist, and not every human-feedback training pipeline uses this exact sequence.

### Real-World Scenarios

- Training chatbots to provide more helpful responses.
- Improving response relevance and conversational quality.
- Reducing undesirable outputs by incorporating human preferences.
- Aligning an assistant's behavior with human judgments.

### Code Snippet: Understanding Preference Data

```python
preference = {
    "prompt": "Explain AI simply",
    "chosen": "AI enables computers to perform tasks...",
    "rejected": "AI is a thing that does stuff."
}

print("Preferred response:", preference["chosen"])
```

This illustrates the preference data used in alignment research. It does **not** train a reward model or perform RLHF by itself.

### Reference Projects

- [Hugging Face TRL GitHub repository](https://github.com/huggingface/trl) — implementation and training examples.

**Remember:** RLHF = *Use human preferences to improve AI behavior.*

## 8. Reinforcement Learning from AI Feedback (RLAIF)

### 1-Liner Definition

**RLAIF** is a training approach in which AI-generated evaluations or preferences help train another AI model.

### Short Technical Explanation

RLAIF is similar to RLHF, but an AI system provides some or all of the preference feedback that would otherwise come from humans.

A typical workflow is:

1. Give a prompt to a language model.
2. Generate multiple candidate responses.
3. Ask an evaluator AI to compare the responses using a rubric or principles.
4. Use the resulting preferences to train a reward model or directly optimize the model using an appropriate preference-learning method.

One important example is **Constitutional AI**, which uses written principles to guide AI critiques and preferences. Anthropic describes a process using AI feedback in a reinforcement-learning phase.

### Real-World Scenarios

- Generating preference labels at scale.
- Improving an AI assistant's helpfulness or harmlessness.
- Evaluating responses against a defined set of principles.
- Reducing the amount of human labeling needed for some training tasks.

AI feedback is not automatically correct. Evaluator models can have biases, miss errors, or reinforce weaknesses in the system being trained.

### Code Snippet: A Simplified AI-Feedback Example

```python
responses = {
    "A": "A clear explanation with a useful example.",
    "B": "An unclear answer with no explanation."
}

# Simulated AI evaluator output
ai_preference = "A"

chosen = responses[ai_preference]

print("AI evaluator preferred:", chosen)
```

This is only a toy illustration of AI-generated preference labels. It does not implement RLAIF training.

- [Hugging Face TRL](https://huggingface.co/docs/trl/) — explore reward modeling and language-model post-training tools.

**Remember:** RLAIF = *Use AI feedback to help improve AI behavior.*

## 9. RLHF vs. RLAIF — Important Differences

| Feature | RLHF | RLAIF |
|---|---|---|
| Full form | RL from Human Feedback | RL from AI Feedback |
| Who provides feedback? | Humans | AI evaluator |
| Feedback source | Human preferences and judgments | AI-generated preferences and judgments |
| Main advantage | Direct human guidance | Feedback can be generated at scale |
| Main limitation | Human labeling can be expensive | AI feedback can be biased or incorrect |
| Example | Humans choose the better chatbot response | An evaluator model chooses the better response |

**Important:** RLHF and RLAIF describe the source of feedback, not one specific algorithm. Both can be implemented in different ways.

## 11. How All the Concepts Fit Together

Consider a robot learning to reach a destination.

```text
1. STATE
   The robot is three steps away from the goal.
          |
          v
2. POLICY
   The robot chooses to move forward.
          |
          v
3. ENVIRONMENT AND REWARD
   The robot moves forward and receives a reward.
          |
          v
4. VALUE FUNCTION / Q-LEARNING
   The agent updates its estimates of how useful the action is.
          |
          v
5. IMPROVED DECISIONS
   The agent balances exploration with exploitation
   and learns a better strategy.
```

RLHF and RLAIF apply related ideas to language models, where feedback evaluates generated responses instead of simply rewarding a robot for reaching a physical destination.
