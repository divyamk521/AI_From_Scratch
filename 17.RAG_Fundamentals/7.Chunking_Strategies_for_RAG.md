Fixed-Size Chunking1-Liner DefinitionFixed-size chunking is a
deterministic text segmentation strategy that divides a document into
sequential blocks based on a strict, unyielding count of characters or
tokens, regardless of paragraphs, sentences, or semantic
boundaries.Short Technical ExplanationFixed-size chunking is the most
computationally simple chunking method. The developer defines a static
boundary constraint---such as chunk_size = 500 characters or tokens. The
tokenizer or character loop counts out exactly that number of units,
cuts the string, and stores it as a chunk before starting the next
block.$$\text{Chunk}_i = \text{Text}[i \times \text{size} : (i+1) \times \text{size}]$$Because
this strategy completely ignores grammar and syntax, it is highly prone
to semantic fragmentation. It frequently cuts sentences directly in
half, breaks words across chunk boundaries, and splits crucial data
values (such as a database configuration value or a product SKU code)
into two separate chunks, blinding the subsequent embedding model to the
complete context.Real-World ScenariosHigh-Throughput Baseline Ingestion:
An engineering team needs to ingest millions of uniform, flat text log
dumps into a vector index quickly. Because the text structure is simple
and they want minimal CPU overhead during ingestion, they use fixed-size
chunking as a fast baseline before optimizing.Recursive Character-Based
Splitting1-Liner DefinitionRecursive splitting is a structural text
segmentation method that uses a prioritized list of separators (like
paragraphs and sentences) to break text down into chunks that fit a
target size while preserving natural language groupings.Short Technical
ExplanationThis is the industry-standard approach for general
unstructured text (implemented as RecursiveCharacterTextSplitter in
LangChain). Instead of splitting text blindly at a hard limit, it takes
a target size constraint along with an ordered list of separation
characters---typically \["`\n`{=tex}`\n`{=tex}", "`\n`{=tex}", " ",""\]
(Paragraphs, Sentences, Words, and individual Characters).The algorithm
attempts to split the document using the highest-priority separator
first (`\n`{=tex}`\n`{=tex}). If the resulting text blocks are still
larger than the target chunk size, it moves recursively down the list to
the next separator (`\n`{=tex}), and then to spaces ( ), until every
individual chunk sits cleanly underneath the maximum size limit. This
approach ensures text is split at the most logical grammatical boundary
possible, preserving the semantic unity of paragraphs and
sentences.Real-World ScenariosStandard Internal Corporate Wikis: A
backend developer is building a RAG application over a company's
internal HR documentation and policy manuals. They use recursive
character splitting to ensure that individual policy paragraphs remain
fully intact within single embedding vectors, preventing answers from
being split across multiple nodes.Sentence-Based Chunking1-Liner
DefinitionSentence-based chunking uses natural language processing (NLP)
tokenizers to locate explicit sentence boundaries, ensuring that every
text chunk contains complete, grammatically sound sentences.Short
Technical ExplanationInstead of relying on basic character counting or
raw spacing tokens, sentence chunking leverages specialized NLP
libraries like NLTK, SpaCy, or SentencePiece to parse the text. These
libraries use pre-trained statistical models to detect sentence endings,
accurately distinguishing a true sentence-ending period from a period
used inside an abbreviation (e.g., "FastAPI v2.0 status code is 200 OK."
vs. "The server crashed at 4 a.m.").Once individual sentences are
isolated, the engine groups them sequentially into single chunks until
the target size boundary is hit. This maintains perfect grammatical
readability for the downstream LLM synthesis stage.Real-World
ScenariosLegal Contract & Compliance Auditing: A regulatory audit
platform ingests long legal briefs and contracts. Because missing a
single conditional clause or punctuation shift can alter the legal
meaning of a text block, sentence-based chunking is deployed to ensure
no sentence structure is ever fragmented during ingestion.Semantic
Chunking1-Liner DefinitionSemantic chunking calculates the statistical
distance between embedding vectors of sequential sentences, placing
chunk breaks only when the thematic meaning shifts significantly between
sentences.Short Technical ExplanationSemantic chunking abandons rigid
character counts entirely in favor of an embedding-driven approach. The
pipeline splits a document into individual sentences and generates a
temporary embedding vector for each one.The algorithm then iterates
chronologically through the text, calculating the Cosine Distance
between sentence $i$ and sentence
$i+1$.$$\text{Semantic Shift} = 1.0 - \text{CosineSimilarity}(\vec{v}_i, \vec{v}_{i+1})$$If
the semantic distance remains low, the sentences are grouped into the
same active chunk. When the distance breaches a calculated statistical
threshold (e.g., the 95th percentile of distance variances across the
document), it indicates a clear change in topic. The engine places a
chunk boundary break there and starts a new cluster. This creates chunks
that vary in length but are perfectly uniform in theme.Real-World
ScenariosComplex Multi-Topic Technical Lectures: A streaming service
builds a RAG engine over transcripts of wide-ranging technical
presentations that fluidly jump between systems engineering, database
tuning, and front-end design. They deploy semantic chunking to ensure
that topic changes naturally dictate where chunks are divided.Sliding
Window Chunking with Overlap1-Liner DefinitionSliding window chunking
moves a fixed sizing frame across a document while maintaining a shared
percentage of text between consecutive blocks, preventing context loss
at the chunk boundaries.Short Technical ExplanationWhen dividing text
into separate chunks, crucial information often falls directly on the
split point. Sliding window chunking fixes this by adding a chunk
overlap parameter. For instance, if you configure a system with
chunk_size = 500 and chunk_overlap = 100, the first chunk captures
characters 0 to 500. The second chunk does not start at 501; it loops
back to start at character 400, capturing characters 400 to
900.PlaintextChunk 1: \[----------------------- 0 to 500

tool processes annual earnings reports. Because crucial metrics are
often framed by introductory context clauses early in a paragraph,
sliding window chunking ensures that key figures are never separated
from their framing conditions.Document-Structure-Aware Chunking1-Liner
DefinitionStructure-aware chunking parses document markup (like HTML or
Markdown tags) to mirror the author's original hierarchy, injecting
section paths directly into the metadata of each text block.Short
Technical ExplanationStructure-aware chunking relies on parsing document
structural syntax (such as \# Heading, \## Section, or DOM structures
like
```{=html}
<article>
```
) instead of treating the document as flat text.The engine uses this
formatting hierarchy to guide its cuts. When a new heading or structural
section is encountered, the current chunk is closed out, and a new one
begins.Crucially, the parser maintains an internal state tree of the
parent layout. A paragraph nested deep inside a document will have its
structural lineage injected directly into its metadata object (e.g.,
{"h1": "System Setup", "h2": "Database Config"}). This ensures that even
small text snippets retain their top-level structural context once
stored inside the vector database.Real-World ScenariosSoftware API

chunking to ensure that short code examples remain linked to their
parent method headers, preventing code snippets from losing context

mathematical heuristics with generative language models. The document
text flows through an LLM orchestration loop. The model reads the text
sequentially and acts as a dynamic supervisor, evaluating content
structure according to explicit formatting guidelines.Plaintext📥 RAW
