# 8. Parent--Child (Small-to-Big) Chunking

## 1-Liner Definition

**Parent--child chunking** is a retrieval strategy that indexes small
chunks for accurate vector search while retrieving larger parent chunks
to provide complete context to the LLM.

------------------------------------------------------------------------

## How It Works

During ingestion:

1.  Split documents into **small child chunks** (e.g., 100 tokens).
2.  Split the same document into **larger parent chunks** (e.g., 500
    tokens).
3.  Link each child to its parent using a unique ID.
4.  Embed and index **only the child chunks**.

During retrieval:

1.  Search the vector database using child embeddings.
2.  Find the most relevant child chunk.
3.  Retrieve its linked parent chunk.
4.  Send the larger parent block to the LLM.

------------------------------------------------------------------------

## Why Use Parent--Child Chunking?

-   High retrieval precision
-   Preserves surrounding context
-   Reduces hallucinations
-   Improves answer completeness

------------------------------------------------------------------------

## Workflow

``` text
Document
    ↓
Parent Chunks (500 tokens)
    ↓
Child Chunks (100 tokens)
    ↓
Embed Child Chunks
    ↓
Vector Database

User Query
    ↓
Retrieve Child Chunk
    ↓
Lookup Parent Chunk
    ↓
LLM with Full Context
```

------------------------------------------------------------------------

## Real-World Use Cases

### Financial Reports

Index small rows for precise retrieval, then provide the full
balance-sheet section for complete financial context.

### Code Repository Search

Index individual functions while retrieving the entire source file or
module so the LLM understands dependencies and surrounding
implementation.

------------------------------------------------------------------------

## Advantages

-   Better semantic precision
-   Richer context for generation
-   Efficient vector storage
-   Works well with large documents
