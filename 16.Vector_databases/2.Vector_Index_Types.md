# 2. Vector Index Types

## Flat (Brute-Force) Index

A Flat Index performs an **exact search** by comparing a query vector
with every stored vector.

-   **Complexity:** O(N)
-   **Pros:** 100% recall, simple
-   **Cons:** Slow for large datasets
-   **Best for:** Small datasets and benchmarking

------------------------------------------------------------------------

## HNSW (Hierarchical Navigable Small World)

A graph-based Approximate Nearest Neighbor (ANN) index using multi-layer
navigation.

-   **Complexity:** \~O(log N)
-   **Pros:** Very fast, high recall
-   **Cons:** High memory usage
-   **Best for:** Production RAG and semantic search

------------------------------------------------------------------------

## IVF (Inverted File Index)

Partitions vectors into clusters using K-Means and searches only nearby
clusters.

-   **Pros:** Low memory, scalable
-   **Cons:** Recall depends on `nprobe`
-   **Best for:** Enterprise-scale search

------------------------------------------------------------------------

## Product Quantization (PQ)

Compresses vectors into compact codes to dramatically reduce storage.

-   **Pros:** 90--95% memory reduction
-   **Cons:** Slight loss in accuracy
-   **Best for:** Billion-scale vector databases

------------------------------------------------------------------------

## Comparison

  Index   Speed       Memory     Recall        Best Use
  ------- ----------- ---------- ------------- --------------------
  Flat    Slow        Low        100%          Small datasets
  HNSW    Very Fast   High       Excellent     Production RAG
  IVF     Fast        Low        Good          Large-scale search
  PQ      Very Fast   Very Low   Approximate   Massive datasets
