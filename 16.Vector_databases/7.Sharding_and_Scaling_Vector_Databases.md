# 8. Sharding and Scaling Vector Databases

## 1-Liner Definition

**Sharding and scaling** distribute vector indexes across multiple
machines so databases can store billions of embeddings while maintaining
low-latency searches.

------------------------------------------------------------------------

## Why Scaling is Different

Unlike relational databases, vector indexes (such as HNSW graphs)
contain interconnected nodes. Simply splitting the graph can break
search quality.

Scaling uses two major approaches:

### Read Scaling (Replication)

-   Duplicate the entire index across multiple nodes.
-   Load balancer distributes search requests.
-   Improves Queries Per Second (QPS).

### Write Scaling (Sharding)

Split the dataset across multiple machines.

**Random Hash Sharding** - Even data distribution. - Query must search
every shard (scatter-gather).

**Semantic (Centroid) Sharding** - Groups similar vectors together. -
Searches only relevant shards. - Lower network traffic and latency.

------------------------------------------------------------------------

## Common Bottlenecks

  Component        Bottleneck        Solution
  ---------------- ----------------- -----------------------------
  HNSW Graph       RAM usage         Product/Scalar Quantization
  Scatter-Gather   Network latency   Semantic routing & replicas
  Index Building   CPU usage         Background batch indexing

------------------------------------------------------------------------

## Production Architecture

``` text
               Client
                  │
                  ▼
      Coordinator / Proxy Layer
          ┌────────┴────────┐
          ▼                 ▼
     Query Nodes       Index Nodes
    (Read Search)    (Build Indexes)
          │                 │
      Multiple Shards   Multiple Shards
```

------------------------------------------------------------------------

## Python Example

``` python
from concurrent.futures import ThreadPoolExecutor

class Shard:
    def __init__(self, name, docs):
        self.name = name
        self.docs = docs

    def search(self, query):
        return self.docs[:1]

shards = [
    Shard("A", ["doc1", "doc2"]),
    Shard("B", ["doc3", "doc4"])
]

results = []

with ThreadPoolExecutor() as executor:
    futures = [executor.submit(s.search, "query") for s in shards]
    for f in futures:
        results.extend(f.result())

print(results)
```
